# AGENTS.md — rules for anyone (human or AI) working on this repo

## What this is
AI Music Reconstruction Studio: turns finished songs (full mix + any stems)
back into editable Ableton Live 12 projects. **A reconstruction engine, not a
generator.** Owner: Erick (SMV, Berlin). Fairly new to dev tooling — explain
steps, don't assume.

## Non-negotiables
- Never invent notes to make music sound better, unless the user explicitly
  picks a creative mode.
- Keep the **raw** transcription separate from any corrected or processed
  version. Every note carries its source (detected / manual) and its confidence.
- Never label estimated notes as exact. Never invent accuracy numbers for songs
  that have no ground truth.
- No mock data that hides a failure. If something doesn't work, say so, and
  ship a working fallback.
- Use only documented Ableton APIs (the Live Object Model via Max for Live).
  Don't reverse-engineer `.als` files.

## How work happens
- The AI works in a **Linux cloud container**. Ableton and macOS exist only on
  Erick's Mac.
- Anything that must run on the Mac goes in `mac/*.command` (double-clickable)
  or in the Live device. Results are written to `reports/` and pushed by
  `mac/_send-results.sh`. Then the AI reads them from git.
- Group Mac tests into as few round trips as possible: Erick's time and the
  usage budget are both limited.
- Work in sprints (see ROADMAP.md). Estimate a sprint's usage before starting
  it. If it is likely to exceed **10% of the usage ceiling**, ask first.
  Progress reports stay short and easy to scan.

## Usage protection — mandatory for every agent

- Work in small, independently testable checkpoints. Reserve capacity for Erick to run Mac/Ableton tests, listen, report findings, and request fixes within the same rolling five-hour window.
- Before substantial work, report the smallest useful deliverable and a **Low / Medium / High** usage estimate. Provide a numerical weekly percentage **only** if actual remaining usage information is available; never invent a quota estimate or claim access to account usage meters.
- **Ask for explicit approval before starting any task estimated to exceed 10% of the remaining weekly allowance.** If the remaining weekly allowance is unknown and the task could plausibly exceed that threshold, ask before undertaking the larger scope.
- Stop at the end of the approved checkpoint. Do not silently roll into another major phase, long autonomous run, or expensive test suite.
- If the five-hour usage window appears close to its limit, pause and provide a concise checkpoint summary rather than exhausting capacity.
- Keep existing working code, especially the verified Ableton Live 12 / Max for Live bridge. Audit and test before replacing it. Make invasive changes on separate branches, preserving original audio, raw transcriptions, and reproducible A/B references.
- For each checkpoint, report what changed, what was actually tested, what remains unverified, and the next smallest user-testable step.

## Product language — English only

- All user-facing Loomback software text must be in English: UI labels, buttons, menus, tooltips, errors, onboarding, reports, documentation, test descriptions, and code comments.
- Use consistent English identifiers and technical terminology in code and APIs.
- The owner may discuss development and give feedback in Spanish; conversation language does not change the product language.
- Do not restrict imported music, vocals, lyrics, filenames, or metadata to English. Preserve original languages and Unicode text.
- Do not translate existing song titles, lyrics, or artist names without an explicit user request.

## Environment
- Python **3.11** in a project-local `.venv`. Versions are pinned in
  `requirements.txt`:
  - `numpy<2`: TF 2.14 crashes on NumPy 2.
  - `setuptools<81`: `resampy` imports `pkg_resources`.
- Linux/cloud: install torch + torchaudio from the CPU index, both 2.11.0+cpu, or
  torchaudio fails to load (`uv pip install --index-url https://download.pytorch.org/whl/cpu
  torch==2.11.0+cpu torchaudio==2.11.0+cpu`).
- Basic Pitch uses TensorFlow on Linux and CoreML on macOS. Use Python 3.11 on
  the Mac too; Basic Pitch 0.4.0's Darwin dependencies are only safe there.

## Layout
```
live/          Max for Live bridge (mrs_bridge.js + MRS Bridge.amxd)
mac/           double-clickable scripts for the Mac
mrs/           Python package (analysis, manifest, CLI: python -m mrs)
tools/         dev / probe scripts (build_amxd.py, probe_transcription.py)
assets/        small fixed test files
reports/       results pushed back from the Mac and from probes
tests/         pytest
```
`live/MRS Bridge.amxd` is generated by `tools/build_amxd.py`. Edit the
builder, not the binary.
